# ABM Milestone 3 — AI-Assisted Model Construction

## Objective

Connect natural-language descriptions to the existing ABM V1 model, validator,
backend registry, and execution engine without allowing the language model to
produce executable code.

## Delivered

- Added a dedicated ABM interpreter using the project's Groq model configuration.
- Added a bounded JSON schema parser for agents, static relationships, behaviour
  conditions/actions, activation policy, termination, and random seed.
- Added Python-side normalization for internal agent references and rule IDs.
  Final executable agent IDs are generated by Python.
- Added strict handling of unsupported fields and behaviour types.
- Added a clarification/refinement loop for missing or invalid model information.
- Added an end-to-end pipeline that validates the typed model, wraps it in the
  shared `SimulationSpecification`, resolves the registered ABM backend, and
  executes only when validation succeeds.
- Added CLI option 3 to create and run an ABM using natural language.
- Added schema and pipeline tests with injected model-generation functions.

## V1 boundaries

- The initial population is expressed as a list of individual agents. Large
  population templates and automatic network generation are not implemented.
- The supported behaviour DSL is limited to the existing state, attribute,
  related-agent-count, composite-condition, and scalar-action types.
- Activation is sequential in declaration order.
- Relationships are static and spatial movement is not supported.
- Termination uses a positive `max_steps` value.
- Missing probabilities and other required operational facts are clarified;
  they are not silently assumed to be certain.
