# M6 — AI-assisted idea interpretation and clarification

M6 turns an initial natural-language idea into a structured, reviewable conceptual draft. It extends the M4 conceptual model and uses M5's local knowledge corpus as optional retrieval context. It does **not** prove a theory, accept mappings, select a simulation paradigm, generate executable rules, or run a simulation.

## Workflow

1. The user supplies an initial idea. The exact original text is retained in `IdeaProject.original_statement`.
2. The service optionally searches the local M5 corpus using deterministic lexical retrieval. Retrieved summaries are passed to the interpreter as leads; scores are labelled as relevance, not confidence.
3. The interpreter returns a strict JSON draft: concepts, properties, relationships, mechanisms, hypotheses, assumptions, constraints, clarifying questions, uncertainties and suggested retrieval queries.
4. Python validates the response schema and all internal concept references. Unknown keys, unsupported enum values, undeclared concept references, and malformed types are rejected.
5. The service asks a bounded number of high-priority clarification questions. Answers are stored verbatim in a separate session audit file and passed to the interpreter for a complete revised draft.
6. The final structured draft is appended to M4 as a new immutable project revision. Open questions remain explicit. Element-level provenance distinguishes verbatim user-grounded material, AI inference and AI suggestions.
7. The CLI saves both the conceptual project and clarification session under `outputs/`.

## Run

From the project root:

```bash
python main.py
```

Choose option **6**. The Groq integration uses the existing `GROQ_API_KEY` environment variable and the existing model setting in `idea_assistant/interpreter.py`. No separate M6 package dependency is required.

For code use, inject an object implementing `interpret(request, knowledge_context=...)` and `refine(request, current_draft, clarification_history, knowledge_context=...)` into `IdeaAssistantService`. This lets tests and other model providers operate without a live API key.

## Provenance semantics

Each conceptual element receives a `ProvenanceRecord` in its revision:

- `user_explicit`: the supplied excerpt was matched exactly against the initial idea or a recorded clarification answer.
- `ai_inferred`: the interpreter derived or organized the element; it requires human review.
- `ai_suggested`: the interpreter introduced an optional suggestion not stated by the user.
- `knowledge_retrieved`: reserved for later source-linked provenance integrations; retrieval hits in M6 are not automatically treated as evidence.

A response field that labels an excerpt `explicit` is **downgraded** to `ai_inferred` when the excerpt cannot be found verbatim in the available user text. Concept objects remain `AI_PROPOSED` because their structured definitions were generated by the interpreter, even when a short concept label is grounded in user wording.

## Safety and epistemic boundaries

- The user's original statement and earlier revisions are not overwritten.
- An AI restatement is a working formulation, not user-approved wording or a verified result.
- Novel concepts can be retained without an existing real-world equivalent.
- AI-inferred relationships and mechanisms remain proposals; correlation is not silently changed into causation.
- Unanswered questions and uncertainties are retained instead of filled with invented values.
- Retrieved source summaries are context leads. M6 does not automatically attach evidence references or accept analogy/equivalence claims.
- The M6 output is paradigm-independent. It is not yet an executable DES or ABM model.

## Tests

`tests/idea_assistant/` tests strict parsing, cross-reference validation, bounded clarification, retrieval-context handoff, provenance downgrade, project round-trip serialization and session audit round trips. Tests use a stub interpreter and do not require a Groq API key.
